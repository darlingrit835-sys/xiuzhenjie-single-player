# Go 与 Java 后端对照

测试在同一台 Apple Silicon Mac 上运行。主对照使用原生 arm64 Go 1.27.4 和原生 arm64 Temurin 11.0.33。Java 使用工程现有的轻量参数（32 MiB 初始堆、256 MiB 最大堆、Serial GC、2 个逻辑处理器），Go 使用 `GOMAXPROCS=2`。每版跑 3 轮，每轮从相同 Java GBK 存档副本启动，暖机后以每秒 12 次的速率跑完 60 次流程，约 5 秒。流程包含 HTTPS 登录、PB 建角与角色登录、查地图、创建并加入副本、进场、施法和离开。每轮测量进程 RSS 与进程累计 CPU 时间。

## 原生 arm64 比较

| 指标（三轮中位数） | Java 轻量档 | Go | 降幅 |
| --- | ---: | ---: | ---: |
| 轮末 RSS | 135.5 MiB | 29.3 MiB | 78.4% |
| 60 次流程累计 CPU 时间 | 1.98 秒 | 0.76 秒 | 61.6% |
| 约 5 秒内平均 CPU（单核为 100%） | 39.6% | 15.2% | 24.4 个百分点 |

原生 Java 各轮 RSS 为 135.3、135.5、136.0 MiB，累计 CPU 时间为 1.87、2.08、1.98 秒。Go 各轮 RSS 为 28.9、30.5、29.3 MiB，累计 CPU 时间为 0.76、0.76、0.82 秒。

本机原先使用的 Unity 自带 Temurin 11.0.14.1 是 x86_64，经 Rosetta 运行。相同流程的中位数为 Java 264.9 MiB / 4.28 秒 CPU、原生 Go 29.8 MiB / 0.84 秒 CPU。两版架构不同，这组数用于对照本机原有运行方式。

## 兼容验证

- Unity 2022.3.62f3 使用现有客户端脚本及界面，在隔离副本上完成登录、选服、PB 查名、建角、场景切换至 `MainScene`、进入 `1111W11` 副本与退出回主城。战斗场景中已观察到玩家和怪物实例，编辑器退出码为 0。
- 测试把 Java 写出的账号与角色存档编码为 GBK，由 Go 直接读取并登录原角色。Go 写入 UTF-8 后，Java 再次登录并进入副本。隔离存档测试同时核对了额外字段和大整数保留。
- 战斗隔离测试覆盖领取掉落、重复击杀结算、装备和技能栏保存。客户端联调与基准测试使用独立端口与存档。

数据对应本机短时负载与 Unity 编辑器流程。 [复现命令](README.md#重现对照测试)


## 纳戒条件读取

Apple M4 Pro 上用 100 件物品和带其他业务字段的角色比较 `1004002`。下表为本机处理、PB 编码与写入测试连接的三轮中位数，每轮 800 ms。

| 路径 | 单次耗时 | 分配字节 | TCP PB 帧 |
| --- | ---: | ---: | ---: |
| 旧版复制角色并重编全量 | 326.8 µs | 260,397 B | 7,430 B |
| 新版首次取完整快照 | 354.1 µs | 207,396 B | 7,448 B |
| 旧客户端命中服务端快照 | 3.04 µs | 17,008 B | 7,430 B |
| 新客户端版本命中 | 0.50 µs | 744 B | 40 B |

新版首包建立可复用快照，单次耗时增加约 8.3%，分配字节减少约 20.4%。版本命中的帧减少 99.46%。网络往返耗时取决于线路。这组数字用于对比纳戒链路。

```sh
cd server-go
go test -run '^$' -bench '^BenchmarkInventory' -benchmem -benchtime=800ms -count=3
```

## 2026-11-21 洞府业务并发

在 Android 1.3.6（38）实际连接的云机上，复制当时运行的游戏服和入口程序，使用独立端口、账号、角色、存档与历史库。测试实例限 1 核、640 MiB。每个角色登录后保持游戏连接，每 3 秒轮换读取洞府、练功房、储物箱和纳戒。下表延迟从同机回环测得，计数为登录完成后的业务请求。

| 同时在线角色 | 持续秒数 | 请求数 | p95（毫秒） | p99（毫秒） | 失败 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 34.10 | 88 | 0.79 | 0.87 | 0 |
| 32 | 34.92 | 345 | 0.72 | 0.81 | 0 |
| 64 | 34.95 | 684 | 0.71 | 0.83 | 0 |
| 128 | 62.93 | 2,560 | 0.69 | 0.76 | 0 |
| 128，续测 | 67.99 | 2,777 | 0.68 | 0.80 | 0 |

共 6,454 次请求，连接中断 0 次。最后一档单独统计的洞府入口 p95 为 0.70 毫秒。游戏服峰值 RSS 32.7 MiB，峰值 CPU 占单核 43%。正式服务的 47 次健康探测 p95 为 5 毫秒，进程重启 0 次。测试结束后已关闭隔离实例并清理测试存档。

随后用相同的正式程序另开隔离实例，将 32 个角色分为四组，每组 8 人，分别执行日常读取、切换修炼路线、箱子改名及存取物品、进入战场施法并离场。62 秒内完成 584 次请求，整体 p95 为 11.21 毫秒，p99 为 14.70 毫秒，零业务错误、零掉线。

| 混合负载中的业务 | 请求数 | p95（毫秒） |
| --- | ---: | ---: |
| 读取 | 264 | 0.71 |
| 修炼及储物写入 | 144 | 12.86 |
| 战场操作 | 176 | 12.30 |

测试服关闭后逐一核对了 24 个发生变化的角色，修炼路线、箱名、灵玉、物品总量和入场精力均符合预期。同期正式服务 12 次健康探测均成功，最慢 5.51 毫秒，两项服务均未重启。第二轮的临时端口和存档也已清理。

本次验证到 128 人并发读取、32 人混合游玩。结果适用于上述请求频率和持续时间，延迟统计范围限于云机回环。
