# 世界内容总表与玩家创作

策划入口是工作簿的「框架总纲」。导表后，服务端按数字 ID 或兼容键读取运行配置，客户端用同版本中文包显示名称。下面列出的命令均可在协作仓库根目录离线执行。[策划总表](../server/data/config_excel/修仙属性基础表.xlsx) · [运行包](../server/data/config/cultivation_affinities.json) · [中文包](../server/data/config/cultivation_affinities.zh-CN.json)

| 从哪里开始 | 怎样查到结果 | 接手说明 |
| --- | --- | --- |
| 新增怪物或战区 | 战区 → 郡、深度与群落 → 本档候选 → 怪物面板、招式、五行与气抗 → 特色材料与奇遇宝库 | [怪物图鉴](bestiary.md) · [怪物数值](monster-stats.md) |
| 创作功法 | 功法 ID → 修炼途径、品阶、属性、词条和图标；修炼组合决定分到各道的修为 | [功法与兼修](cultivation-methods.md) |
| 新增人物与掉落 | 战区 → 本地修士 → 功法和随身物 → 对应档位的秘籍、法器、消耗品 | [人物与掉落](character-encounters.md) |
| 追溯一件物品 | 物品模板 → 配方或采集／妖兽来源 → 郡；器谱、丹方和符方共享同一套物品与用料 | [造物](item-creation.md) · [炼丹](alchemy-design.md) · [画符](inscription-design.md) |
| 填数值与可用词条 | 门类、物品分类或模板指定词条组，按权重不放回取数，以阶定条数、以品定区间 | [内容词条与产量](content-affixes.md) |
| 新增其他玩法 | 栽培、阵位、宗门与家族建制、招式、对战、拍卖规约均有主表、细表与种子数据 | [玩法表与引用](world-systems.md) |
| 玩家留影 | 已完成战报 → 角色当时的面板、功法与器物版本 → 同图随机遭遇 → 胜利回执与掉落槽位 | [投影与存档](historical-projections.md) |

## 模板、版本与实例

「创作门类」登记可查的运行目录和是否开放玩家创作。「模板索引」将每个已入库的对象映射成 **门类 ID＋模板 ID**。数字原生表直接沿用本表的主键。原物品、丹方、符方保留现有程序键，同时有明确的数值映射。新增行分配未用过的整数并登记，排序和翻译不影响引用。「图标目录」将独立图标 ID 关联至 Unity 资源键。

- 系统模板使用正整数且小于 10 亿。玩家模板预留 10 亿至 2,147,483,647，按门类分配。协作版新增模板在服务端事务中领取序号，唯一约束兜住并发，分配号永久保留。
- 玩家可以为新模板自由命名。名称、作者、来源原型、发布版本、实例 ID 各自独立。制作新物品产生的随机数值固定在实例上。作者后续更名、改良功法时新增版本，已售装备、已学秘籍和历史投影按保存的版本解析。
- 自创功法可以独立起稿，或从一个同类已发布版本衍生。需要原型的门类可在表里开启「需要原型」。物品的原型细表和用料还按原有校验执行。选择已有图标时只引用其数字 ID。富文本、文件路径、名称拼接均不参与寻图。
- 存档框架包括门类、模板身份、版本快照和版本间引用。草稿可修改，发布后锁定；下架保留旧引用。可按作者查模板，也可反查一个版本有哪些下游作品。新增一种创作内容时在「创作门类」登记其运行目录并提供该领域的参数校验。[SQLite 表结构](../server/data/schema/player_content.sql)

## 图标格式

每个交付图标都是 **256 × 256、透明底、单 Sprite**。怪物按身体轮廓与物种特征表现，功法采用书册装帧和封面纹样。图片内不放汉字、字母、数字、题签或印文。玩家名和展示名称由界面另行排版。资源键为 `CatalogIcons/Monsters/<数字>` 或 `CatalogIcons/Methods/<数字>`，新图使用新键和唯一 Unity GUID。图标登记适用门类；0 表示通用。可以先上架供创作者选择的空闲式样，再关联作品。换名字不需要重新绘图，同一外观可以被多件玩家作品引用。[图标目录](../UnityProject/Assets/Resources/CatalogIcons) · [怪物预览](images/monster-catalog.png) · [无字书册预览](images/method-catalog.png)

客户端为 41 种怪物与 50 部功法提供 123 张无字图标。新增 16 张兽像、16 张书册。宗门兽潮从「界面图池」的 `beast_wave` 等概率选兽像，野外与塔战按旧对象类型和旧图标的组合查对应物种。功法换装、参悟、兑换和可识别功法模板的纳戒秘籍按模板取封面；观想图、淬体诀、玄水真经分别启用桂轮白兔、金鳞护臂、螺音潮生。[新增式样预览](images/icon-variants.png)

`python3 tools/export_affinities.py` 同时生成游戏取图索引。为新功法换封面时修改「功法目录」「模板索引」两个图标 ID；要给宗门兽潮增减外观，只改「界面图池」成员。图片按需载入，反复显示复用同一张 Sprite。未知旧模板继续使用游戏提供的原图。[Unity 图标索引](../UnityProject/Assets/Resources/CatalogIcons/index.json)

## 性能与核对

- 导表时校验类型和引用，建立地图键、模板键、功法旧键、材料来源等反向索引。运行时进入一个子图只读本群落、当前档位的候选，具体面板在选中遭遇时计算。图鉴目录可直接读基础数值。
- 正式服务应以目录哈希缓存解析结果，按资源键按需加载图像。只在发布或制作成功时保存作品快照；玩家的草稿、投影和背包实例独立存储。投影只取同图其他作者的最近一席，普通查询和重复请求均可走索引。
- 已有地图的三个深度、旧 48 个功法键和旧极品数据保留兼容。静态导出会检查完整地图覆盖、空怪池、非法兽王、缺面板或抗性、断开的来源链、重复编号和缺图。套装数值、掉落经济与真实玩家留影还需要上服试玩和观测。

```sh
python3 tools/export_affinities.py --check
python3 -m unittest discover -s tools -p 'test*.py'
python3 tools/preview_monster.py --map 1111W11 --monster 青岚螳 --level 1
python3 tools/preview_character.py --character 槐素秋 --tier 3
python3 tools/preview_projection.py --map 1111W11 --seed 31
```

## 本轮发现并修正的边界

| 原因 | 现在的验证或处理 |
| --- | --- |
| 用“功法名等于属性对象名”判断引用，会挡住自由改名 | 按稳定 ID、对象类型和维度校验；回归测试只改显示名，核对资源键与模板 ID 保持一致 |
| 郡里登记了怪物和掉落，具体战区却可能没有对应档位 | 编译时逐一校验 108 个原战区，发现空群落、错郡或所有可遇档掉率均为零就返回行级错误 |
| 同一作者连续通关、重复入场或重复结算会影响遭遇与收益 | 同图作者只占一席。遭遇回执固定第一次的抽取；胜利回执保留零掉落，奖励槽位唯一 |
| 多件作品同时提高产量或减少投入，可能产生免费制作或超过成品上限 | 按独立来源限件叠加，再压到作用上限。正用量至少实扣一份，玩法的成功率和符纸等实物上限继续生效 |
| 批量改名或提前添加美术会让图标索引失效 | 图标独立编号、登记适用门类，可在玩家选用前先入库。导表核对尺寸、透明通道、Unity GUID 及 Sprite 导入类型 |

## 后续接入

历练服务在开战时选候选并锁定规则版本，在击败时结算材料、秘籍、法器与背包实例。修炼服务需要接入功法发布、学习、装配、角色权限和外部提交的字段校验。客户端需要接入图鉴、词条预览、玩家命名和作品详情。随机投影还需要真实角色授权、战报签发、旧规则归档、到期清理与奖励入库事务。当前仓库中的配置、离线预览与临时数据库可以独立重放这些引用。
