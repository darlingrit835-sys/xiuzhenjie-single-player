# 联机测试与全量热更新

## 手机怎么测

1. 安装测试渠道的 Android **1.3.5（30）**。这个 APK 支持 `armeabi-v7a`。
2. 打开游戏。安装包内含完整代码和资源，首次启动完成本地校验和解压后进入登录。
3. 联网登录、选择修真界并进入主城。新测试账号在测试服建立角色。

这个测试版本暂停经脉入口和强制经脉引导，便于继续测试进城。

当前云端版本已通过公网登录、建角、角色登录和战斗连接检查。Unity Play Mode 已验证首启读取内置资源、登录、选服和进主城。Android 真机仍待试装。

## 热更覆盖范围

| 交付项 | 更新入口 |
| --- | --- |
| 玩法 C#、客户端 PB 协议、场景、界面预制体、贴图、音频和配置 | 使用当前 Android 基线导出并签名发布，客户端重启时校验并加载。 |
| Unity 引擎、IL2CPP 原生代码、Android 插件、启动图标、更新频道地址和证书指纹 | 更新 Android 安装包。 |

同一个签名清单关联本次代码和资源。客户端校验基线兼容标识、RSA 签名和 SHA-256。同一版本再次启动时复用已校验缓存。首次启动使用 APK 自带版本。后续启动发现更新时，通过 HTTPS 分段下载，校验完成后加载新版本。

## 开发者发布流程

以下入口位于包含 HybridCLR、全量启动器和网关的完整测试发行工程。仓库的本地 Unity 构建入口见 [Unity 工程说明](../UnityProject/README.md)。

1. 构建带完整资源的 Android 安装包。用 Unity 2022.3.62f3 执行 `RecoveryAndroidBuild.RunFull`，目标设为 Android，传入 APK 输出路径 `XIU_RECOVERY_APK`、频道配置路径 `XIU_FULL_UPDATE_CONFIG` 和递增的 `XIU_ANDROID_VERSION_CODE`。同时传入热更输出路径 `XIU_HOTUPDATE_OUTPUT`、版本 `XIU_HOTUPDATE_VERSION` 和签名私钥路径 `XIU_FULL_UPDATE_SIGNING_KEY`。构建会导出并嵌入签名版本，留存输出中的 `base.json`。
2. 单独发热更时导出客户端版本。执行 `ClientReleaseBuild.ExportRelease`，使用该基线的 `XIU_FULL_UPDATE_BASELINE`，并指定 `XIU_HOTUPDATE_VERSION` 和 `XIU_HOTUPDATE_OUTPUT`。
3. 使用 `Tools/hot_update.py sign-full` 生成签名。发布签名私钥和测试频道凭据存放在仓库外。
4. 校验并上传 `client-release.zip` 到 `releases/<archiveSha256>/`，再发布 `manifest.sig` 和 `manifest.json`。网关用 `-full-hot-update-dir` 启用全量频道。新 Android 基线放在 `channels/<APK 版本号>/` 下。通过 HTTPS 核对清单签名和压缩包摘要。
5. 在测试端重启，检查版本下载、登录、选服和进城。玩法调用变更涉及服务端 PB 字段或回包时，同步验证对应后端。
