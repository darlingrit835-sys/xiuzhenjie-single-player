# 修仙属性框架总纲

先定天地属性，再定物品与玩法。阴阳回答“力量如何显现”，五行回答“主要擅长什么”，十二气回答“它具体以什么形态作用”。一件器物可以与一门术法同属阴金寒气，各自仍有独立的模板、材料、用途和品阶。[策划工作簿](../server/data/config_excel/修仙属性基础表.xlsx) · [运行配置](../server/data/config/cultivation_affinities.json) · [简体中文资源](../server/data/config/cultivation_affinities.zh-CN.json) · [物品分类与玩家创制](item-creation.md)

## 本轮先定哪些表

本版供策划审表。先打开工作簿「框架总纲」，沿下面三条引用链阅读。表内已有的词条数、数值区间、火种和配方都作为首轮平衡样例。

| 从哪里读 | 沿什么键往下查 | 要定的设计 |
| --- | --- | --- |
| 五行侧重、阴阳侧重 | 行或阴阳 ID → 属性键；再用阴阳、主行、主气定位类别 | 金攻、木生、水疗、火炼、土御的分工，以及每一种气在不同分支中的权重 |
| 物品总表 | 模板键 → 分类、对象属性、品阶 → 材料或武器细表 → 固有词条及用料 | 同类物品可以怎样分化，玩家新品应继承哪些引用 |
| 炼器工艺、功法工艺 | 师阶、火种、目标品阶和已装备功法 → 生克规则 → 工艺收益；成功后按品阶选取成品词条 | 炼制来源如何起作用，失败返还什么，成功后揭示什么 |

以**玄阶上品**为例，物品存整数 `7`。从品阶表取到玄阶与上品，当前玄阶给两种不同词条，上品给各自的取值上下限。若成品主金，首条为攻击力，上品攻击取 +2.70%～4.00%。炉火的「淬灵」可以让抽值偏向上沿，成品的两条词条仍在成功开炉时才揭示。[炼器规则样例](smithing-workshop.md)

## 一轮设计怎么走

1. **定侧重。** 五行侧重规定每一行的主属性，阴阳侧重规定外放或蓄养的加成。属性键在「加成条目」中只有一份定义。
2. **写气相。** 在「阴阳配气」和「五行配气」分别说明同一种气如何显现，并给相对权重。例如寒气在阴为凝霜、在阳为迸冰，在金为寒锋、在水为凝冰、在土为冻壤。
3. **分阴阳，定区间。** 每一行各分阴、阳。到「分支加成」为每个分支选条目、定上下限。
4. **组合与抽样。** 每个分支都可以取十二种主气，形成 120 个候选类别。可固定种子抽 48 个，用结果检查常见程度和数值分布。
5. **落实物件。** 给材料、武器、丹药等建立模板，引用属性对象，再按物品种类填写细表和用料。法术、阵法、传承、山峰等也可直接引用属性对象。
6. **回到规则调整。** 某个气相出现太频繁，调配气权重；类别合适但效果过强，调分支区间；要新增命名的剑、丹方或矿石，增模板和用料。同一配置与种子可对照前后两轮。

## 五行与阴阳如何分工

下表给出首版的五行主项区间。每个阴分支还可以延长有时限的正面状态，每个阳分支还可以加强直接命中。两项分别命中自己对应的使用场景。

| 五行 | 主要侧重 | 阴支主项 | 阳支主项 |
| --- | --- | ---: | ---: |
| 金 | 攻击力 | +3.00%～6.00% | +5.00%～8.00% |
| 木 | 生命上限 | +6.00%～10.00% | +4.50%～8.00% |
| 水 | 疗伤量 | +5.00%～9.00% | +3.50%～7.00% |
| 火 | 炼器时每次成功操作推进的进度 | +4.00%～7.00% | +5.50%～9.00% |
| 土 | 防御力 | +5.50%～9.50% | +4.00%～7.50% |

首版用整数基点存储加成，100 基点等于 1%。单项计算为 `基础值 × (10000 + 加成基点) / 10000`。例如阳火的炼器进度抽到 700 基点，基础进度 100 的一次成功锻造推进 107。同一阳火类别所带的直接伤害条目只在直接命中时使用。取整、疗伤上限、多件装备叠加及生克倍率在对应玩法结算时定义。

## 总表与细表如何引用

| 工作表 | 唯一键或关联 | 导出字段 |
| --- | --- | --- |
| 阴阳、五行、十二气 | 三套独立编号；五行的「生」「克」引用五行编号 | `polarities`、`elements`、`qiTypes` |
| 加成条目 | 属性键，如 `smithing` | `stats` |
| 阴阳侧重、五行侧重 | 一个极或一行 → 一个主属性键 | `polarityFocus`、`elementFocus` |
| 阴阳配气 | 阴阳编号 × 气编号，2 × 12 行 | `polarityQiWeights` |
| 五行配气 | 五行编号 × 气编号，5 × 12 行 | `elementQiWeights` |
| 分支加成 | 阴阳编号 × 五行编号 × 属性键，首版十支各两条 | `bonusRules` |
| 品阶表、旧极品对照 | 物品持有一个数字 `gradeId`，常规十二档查品阶表，原有四档极品查历史对照 | `grades`、`legacyGrades` |
| 词条数量、词条区间、物品词条、炼器工艺 | 按阶查数量、按品质查上下限、按模板查固有词条、按工艺来源查收益 | `affixCounts`、`affixRanges`、`itemAffixes`、`forgeEffectRanges`、`forgeFactors` |
| 功法工艺 | 玩法键 × 功法类型 ID × 已装备功法品阶 ID → 五行作用倍率 | `methodInfluences` |
| 衍生类样例 | 首版固定种子的 48 类抽样快照，可用生成器复现 | 生成器输出的 `id` 与 `bonuses` |
| 对象属性 | 对象键 → 阴阳、主辅五行、主辅气。以三项主分类推导 `classId` | `profiles` |
| 物品分类、物品总表 | 分类树的叶子 ← 物品模板 → 属性对象 | `itemCategories`、`itemTemplates` |
| 材料表、武器表、造物用料 | 加工和持用说明按模板键查中文资源；配方按产物键和材料键查数量 | 中文资源里的 `materialDetails`、`weaponDetails`，运行配置里的 `creationInputs` |
| 类型与玩法、玩法用法 | 类别键、玩法键各有字典；一个玩法可以引用多个对象 | `profileKinds`、`systems`、`profiles` 中的 `kindId`、`systemProfiles` |

## 地域与产出怎样接入

从「地域总表」沿大陆、洲、郡读取阴阳、五行与主气。「地域词条」连接玩法、作用目标及本地修士共鸣；「地区怪物」「地区物产」登记当地能遇到的怪物和资源点。当材料既能采得、又可由妖兽产出时，两条来源共用同一物品模板，炼器、种植、炼丹、画符分别按用途引用。[六郡地利、产出与离线预览](region-ecology.md)

## 后续玩法怎么接同一套表

「类型与玩法」登记玩法键，「玩法用法」登记玩法引用的属性对象。下表列的是工作簿里可顺着键查到的样例。后续专用细表各自维护本玩法需要的数值。

| 玩法 | 已登记的对象 | 后续专用细表可承接的内容 |
| --- | --- | --- |
| 炼器、炼丹 | 霜纹铁、凝露草、凝露丹 | 器方与丹方连接原料和成品。炼丹细表和产地查询见[炼丹规则草稿](alchemy-design.md) |
| 画符、阵法 | 澄露墨、轻身符、迷踪阵 | 符纸与符墨用量，阵眼与阵材的位置 |
| 灵植 | 凝露草、青壤 | 植株模板与土壤的适性、生长周期 |
| 宗门、家族 | 炼丹峰、槐阴氏祖传心法 | 山峰传承、家传功法及其属性引用 |
| 战斗、对战 | 引雷术 | 同一招式模板，分别引用各模式的结算规则 |
| 拍卖行 | 霜纹剑、凝露草、轻身符 | 挂单引用物品模板和实例，交易沿用已经生成的作者与词条 |

新增玩法时，优先复用现有模板、对象、品阶和属性键。例如凝露草同时供炼丹、灵植与交易引用，改玩家可见名称时只改一份中文资源。宗门、家族、功法等独立成长对象用自己的对象键；若需要专属收益，细表用「对象键 × 效果键」引用，另存触发条件、作用目标和计量单位。拍卖挂单的价格与持有人跟随挂单和实例，物品固有词条跟随作品模板。

## 存什么，什么时候查

| 记录 | 运行配置与存档用键 | 查中文的时机 |
| --- | --- | --- |
| 阴阳、五行、十二气、品阶 | 数字 ID，权重、基点和配方数量也用整数 | 展示“阴”“金”“寒”“玄阶上品”等名称时 |
| 类别、模板、属性对象、属性条目、玩法 | 稳定的 ASCII 键，例如 `wp.sword`、`made.frost_sword`、`weapon.shuangwen`、`healing`、`auction` | 图鉴、说明、搜索或界面展示时，使用同一个键查当前语言资源 |
| 自创作品与库存 | 服务端分配长期模板 ID，成品实例有自己的 ID；记录版本、已抽数值等个体差异 | 玩家改名时更新作品的显示名，已有配方和挂单继续引用原键 |

导出器由一份 Excel 生成两个带相同 `catalogVersion` 的文件。运行配置按键组织，中文资源按相同键存名称、气相表现及物品说明。JSON 对象的数字键在文件中写作 `"7"`，模板内外键 `gradeId` 的值仍是整数 `7`。加载端核对版本后再将两份一起用于展示。战斗、选材和配方计算可以只读运行配置。

例如，读取 `itemTemplates["made.frost_sword"]` 取得分类、属性对象和品阶，再以模板键访问 `creationInputs["made.frost_sword"]` 可直接拿到整份用料。Go 读取包在加载时另建“材料 → 产物”的反向索引，材料图鉴打开后可以只遍历使用该材料的配方。按模板或品阶单查使用映射；查一份配方的成本与该配方的材料种数有关。[Go 只读查询包](../server-go/internal/affinity)

### 把同一条类别从头查到底

以 **阴金·寒气** 为例。阴编号 1、金编号 1、寒气编号 3，合成稳定键 `affinity.p1.e1.q03`。

- 查「阴阳配气」的 **阴 × 寒** 得“凝霜”，权重 5。查「五行配气」的 **金 × 寒** 得“寒锋”，权重 4。这一类别的抽样权重为 20。
- 查「分支加成」的 **阴 × 金**，攻击力可抽 300～600 基点，增益时长可抽 350～650 基点。首版 48 类样例中，这一类分别抽到 **+4.64%** 和 **+4.84%**。
- 查「对象属性」的 **寒纹铁**，它是阴、主金、主寒，因此关联这一个类别。其辅水、辅罡继续保留，可为选材提供更细的条件。同类的不同材料、武器或术法可以拥有不同对象键。

### 分类有多少，物品能增加多少

十二气固定为风、雷、寒、炎、润、燥、生、煞、清、浊、罡、幻。2 个极、5 个主行和 12 种主气给出 **120 个基础类别**。配气权重均为正数，每个组合都有机会入选。每轮按剩余候选权重比例抽一个，移除已抽项，直至达到指定数量。加成按各条区间独立取整数，包含两端。

“平和”继续用于明确阴阳调和的对象。主属性未定的旧物品、或平和对象，仍可通过对象键与物品模板正常引用，`classId` 留空。旧五行的 0 按原字段语境保留。药材原有四气、归经、角色复灵根继续各自使用原字段。

**物品数量不受 120 限制。** 同类可继续细分辅行、辅气、材料形态、武器形制、原型和配方。新的基础加成只需先增「加成条目」，再把它加入所需的分支。扩充基础维度本身属于换版，应保留已有编号、扩充交叉表，并同步更新导出器和生成器的维度校验。

## 品阶用数字引用

物品只存整数 `gradeId`。名称和倍率在「品阶表」维护并由材料、武器和玩家造物共用。下表按天至黄展示，各格为对应的品阶 ID。

| 阶 | 上品 | 中品 | 下品 | 原有极品 |
| --- | ---: | ---: | ---: | ---: |
| 天 | 15 | 14 | 13 | 16 |
| 地 | 11 | 10 | 9 | 12 |
| 玄 | 7 | 6 | 5 | 8 |
| 黄 | 3 | 2 | 1 | 4 |

新作品从十二个常规 ID 中选取。项目原有四档极品在「旧极品对照」中保留可查，原筑基丹（黄阶）用 4，原五行聚灵剑用 12，一阶陨铁用 16。旧物品的 `Stage` 独立表示阶数，同一阶数可出现不同 `Rank`。[原商品数据](../server/data/config/xuantianlougoods.json) · [项目原品阶顺序](../server/src/server/game/modules/cultivation/GameData.java)

炼器时，黄、玄、地、天分别赋予 1、2、3、4 种不同词条。每种词条按下、中、上的专用区间取值。旧极品仅供原物品查询。品阶表中的倍率用于新武器的基础攻防，例如玄阶上品 ID 7 的倍率为 13000。炼器工艺的成色修正只改变词条在指定区间内的位置。[炼器工坊](smithing-workshop.md)


## 导出、抽样与复现

在仓库根目录执行，使用 Python 3.9 或更新版本的标准库。

```sh
python3 tools/export_affinities.py
python3 tools/export_affinities.py --check
python3 tools/generate_affinity_classes.py --seed 20261120 --count 48
python3 tools/generate_affinity_classes.py --seed 20261120 --count 48 --grade-id 7
```

省略 `--count` 默认抽 48 个，传 `--count 120` 可查看全部组合。加 `--output 文件名.json` 可保存该批结果。固定配置与种子时，扩到 96 或 120 会保留原来 48 条的顺序及数值。换种子可生成另一批。类别键始终表示同一个三元组，批次中的具体加成应随成品或批次快照保存。工作簿「衍生类样例」展示首版的基准加成。传入 `--grade-id` 后，输出保留数字品阶 ID、基准基点、按阶选取的词条和品质区间内的最终基点。[导出器](../tools/export_affinities.py) · [类别生成器](../tools/generate_affinity_classes.py)
