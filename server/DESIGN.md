## 二、布道/创造功法黑盒算法设计（用户最在意）

### 官方原版特征（用户回忆，已无法还原）
- 先取余弦函数 → 再取一个圆 → 再取某图形函数（中科大数学系研究生搞的）
- 从落点里找能成功/不能成功的创造
- 小数点 6 位精度，动 0.0001 变化都很大 → 典型的混沌/分形系统（对初值敏感依赖）

### 我们方案：Julia 集混沌迭代（行为等价）
```
输入：AcupointId[]（穴位序列，b.json 穴位表63穴，每穴有五行/经络/缓急）+ Stage（品阶）
1. 序列编码：每穴位五行相位累加 + 相邻穴位五行生克偏置 + Stage 缩放 → 复数 c
2. Julia 迭代：z₀=0，zₙ₊₁ = zₙ² + c，上限 N（256），逃逸半径 2.0
3. 逃逸 = 失败；N 次不逃逸 = 成功
```

### 输出映射（Resp 20 字段全覆盖）
| 字段 | 映射 |
|---|---|
| CreatedIsSuccess | 逃逸/收敛 |
| ActionScope | 逃逸前迭代次数（离成功多远） |
| MaxStep / RunSpeed | 迭代上限 / 收敛速度 |
| FiveElement | 收敛点幅角 → 五行扇区，按玩家灵根加权偏移 |
| Rank / Stage / MinLevel / MaxLevel | 品阶 × 收敛质量 → 阶位/等级范围 |
| EffectType1/2 | GongFaEffectTypeEnum 20 种效果池按五行权重抽取 |
| EffectValue1/2 | 三档（10/20/25）按收敛精度映射 |
| ConversionRate | 收敛质量（double） |
| CurrentClever | 悟性消耗（失败扣少/成功扣多，按品阶） |
| LiveLevel / LiveProficiency | 创造后灵根成长（成功+） |
| CreatedBy | 玩家名 |

## 三、工程背景认知（决策依据，勿重新纠结）

- **官服活着 vs 死了**：活着=抓包抄答案（rea+frida 跳过客户端门槛→mitmproxy 抓真实响应→照抄，约150~300小时）；死了=自行设计（当前，约600~1200小时）。差距3~5倍，多出的是算法设计+数值平衡。
- **rea 用法要点**："等级/实力不够"弹窗多是客户端本地检查（已反编译可确认），frida hook 判定函数返回满足值即可发请求；服务端是否拦要看错误码（小厂通常不拦）。当前官服已死，rea 无用武之地。
- **rea 同级工具**：GhidraMCP/IDA MCP（AI 接口）、angr（符号执行，对残留 so 算法反推最强）、Frida+Objection（动态插桩）、JEB（安卓商业）。rea 是整合度最高的 AI 逆向 agent，单点深度不如 IDA/angr。
- **WorkBuddy**：腾讯 AI 编程 agent，与当前使用的 opencode 同层级。"WorkBuddy+rea"=AI agent 驱动逆向工具集，本质就是本项目现在的工作模式。换 agent 会丢失本项目全部上下文积累。
- **协议缺口认知**：服务端判定算法（如布道黑盒）与动态数据（怪物/掉落/拍卖行）从未下发到客户端，无法还原官方原版；只能自建等价物（算法行为等价 + 数据自造平衡）。复刻官方做不到，"做一个能玩且好玩的"完全可行。
